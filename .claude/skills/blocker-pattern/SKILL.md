# Blocker Pattern

Something keeps not happening. The job is not to solve this instance — it's
to show that it IS a pattern, name its mechanism, and test that against the
user.

## Method

1. **Collect the instances.** Search journal entries, weekly reviews,
   end-of-day carries, and past commitments for the same obstacle wearing
   different clothes. Three instances minimum before calling it a pattern —
   below that, say it's too early to call.
2. **Name the mechanism, not the symptom.** "You didn't ship" is a symptom.
   The mechanism is what reliably precedes it: the task needs a decision
   the user is deferring, requires an ask they're avoiding, or only has
   consequences someone else sees.
3. **Classify it:** missing skill, missing information, missing decision,
   or avoidance. Say which — the responses differ, and misclassifying
   avoidance as a skill gap wastes months.
4. **Ask the one question.** End with a single question that tests whether
   the named mechanism is right. One. The user answering it honestly is the
   session's real output.

## Output

- **The pattern:** one sentence.
- **The evidence:** the instances, dated, quoted or paraphrased from the
  user's own entries.
- **The mechanism:** what actually stops the work, classified.
- **The question:** one, specific, uncomfortable if it needs to be.

No advice until the user responds to the question. Pattern first, agreement
second, fix third.
